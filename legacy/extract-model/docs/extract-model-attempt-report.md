## 5. 원인

- **59건 모두 같은 지점에서 마감이 비었음**(로컬 재현값, 반영 직후 관측값과 59/59 일치)

  - 알림톡은 발송일 기준 날짜 보충도 꺼져 있었음(`kakao.py:40`)
- 원인은 추출 모델 점수만이 아니라, **"마감은 모델만"으로 정한 합치는 방식**
- 59건 원문 분류(Claude 판정)

| 분류 | 건수 |
|---|---|
| 명시된 마감 누락 | 16 |
| 기존 규칙의 오탐 제거(근로기간·행사 일시 등) | 27 |
| 판정 불가(설문·진단검사 기간 등) | 16 |

- 명시 누락 16건의 세부
  - 문턱 바로 아래(0.94~0.95)라 탈락: 3건(3239 0.9481, 3221 0.9438, 6e31 0.9491)
  - 근거 줄이 1위지만 점수가 더 낮음: 10건
  - 표가 줄마다 쪼개져 엉뚱한 조각이 1위: 2건(0095, 0098)
  - 같은 공고의 다른 마감 줄이 1위: 1건
- 입력 잘림은 원인이 아님. 명시 누락 공고에 잘린 줄 없음
- 사전 검증에서 못 거른 이유
  - 합격 기준에 "규칙이 찾은 명시 마감을 몇 건 잃는가"가 없었음
  - 사람 정답에 알림톡이 없었는데, 사라진 59건 중 47건이 알림톡
  - 확인 안 한 가설: 문턱은 GPU 예측으로 골랐고 운영은 CPU 예측(11/18 확인 때 확률 차 최대 0.11)

## 7. 보류 이유

- **효율 이득 없음**
  - 요약은 여전히 Gemma만 할 수 있어 공고마다 Gemma를 호출함(공고당 중앙값 4.5초)
  - 추출 모델 약 0.1초가 더해질 뿐
  - 11/25 반영 배치 49분은 Gemma 전체 재분석과 같은 수준
- **정확도 이득이 작고, 대부분 모델 밖에서 옴**
  - 마감 개선은 날짜 파서 덕분이라 모델 없이도 얻을 수 있음
  - 모델만의 이득은 직접 확인 조건 재현 +15%p(참고 라벨 기준) 하나
  - 사람 정답(명지 20건)에서도 포착은 25 → 31로 늘었지만, 정밀도는 사람 정답으로 잰 적이 없음
- **유지 부담**
  - torch·transformers 의존성, 가중치 225MB, 배치 설정 분기가 늘어남
