## 3. 사라진 59건 분류 (원문 기준, 한 건씩 판정)

판정 기준(SPEC §5 `application_deadline` = 신청 마감, 근로·활동 기간은 마감 아님(rule-0.5)):
- **명시된 마감 누락**: 원문에 신청·접수·모집·제출 마감이 적혀 있음(`~까지 신청`, `모집기간`, `접수기간`, `…까지 제출` 등)
- **기존 규칙의 오탐 제거**: 규칙이 잡은 날짜가 신청 마감이 아님(근로기간, 운영·수강·교육·행사 기간, 지원기간, 투표·검진 일시, 교재 배부, 공고 작성일)
- **판정 불가**: 신청 절차 없이 참여 기간만 있음(설문·만족도 조사·진단검사 기간). 또는 기간 이름이 없어 원문만으로 신청 마감인지 정할 수 없음

  - **문턱 바로 아래(근거 줄이 1위, 0.9~0.95)**: 3건. 3239, 3221, 6e31
  - **근거 줄이 1위지만 점수가 더 낮음(0.16~0.90)**: 10건. 예: 국가장학금 997 0.9031, `모집기간 : ~ 2026.06.12.(금)까지` 0.8311, `▪ 신청기간: ~ 11/8(일)` 0.616, `신청 마감 : 4/29` 0.1585

## 5. 왜 사전 검증에서 못 걸렀나 (확인된 것만)

- 합격 기준이 "맞은 마감 수·틀린 마감 수·만든 마감 수"였고 **"규칙이 찾은 명시 마감을 몇 건 잃는가"**는 재지 않았습니다.
  - 시험 94건의 놓침 9건은 규칙 8건과 비슷해 통과했습니다(`docs/extract-model.md` 재측정 기록).
- 실제 반영 대상 465건 중 알림톡이 296건으로 가장 많았습니다. 반면 사람 정답 평가셋(명지 20건)은 게시판 공고뿐이었습니다. 사라진 59건 중 47건이 알림톡입니다.
- 가설(확인 안 함): 문턱 0.95는 5070 GPU 예측으로 검증 세트에서 골랐고, 운영은 CPU로 예측합니다.
  - 11/18 확인 때 CPU·GPU 확률 차가 최대 0.11이었습니다(문턱 근처 줄의 판정이 갈릴 수 있음).
  - 이번에는 GPU 점수를 다시 내지 않아 3239 등이 GPU에서 0.95를 넘는지는 모릅니다.

## 6. 최소 수정안

확인된 원인(문턱 미달 시 규칙 마감 덮어쓰기, 알림톡 보충 꺼짐, 0.95 바로 아래 점수)에 맞춘 순서입니다.

1. **규칙 마감 지우기 조건을 좁힘(가장 작은 수정)**
   - `_deadline`에서 모델 1위 점수가 문턱 미만일 때 무조건 null로 만들지 않습니다.
   - 규칙이 잡은 마감의 근거 줄이 신청·접수·모집·제출·마감 표현을 포함하면 규칙 마감을 남깁니다(규칙의 기존 판별·정규식 재사용).
   - 오탐 27건은 대부분 근로·운영·수강·행사 기간이라 이 조건에 걸리지 않을 것으로 예상합니다. **예상일 뿐이며 검증 필요.**
2. **문턱을 CPU 예측 기준으로 다시 고름**
   - 운영과 같은 CPU 예측으로 **검증 세트**에서 고릅니다. 시험 세트나 이번 59건을 보고 고르지 않습니다(명세 §5-3 원칙).
3. **알림톡 날짜 보충**
   - 1을 적용한 뒤에도 알림톡의 명시 마감이 비면, `kakao.py:40`의 `deadline=False`를 "모델·규칙 둘 다 마감이 없을 때만 보충"으로 좁히는 안을 검토합니다.
4. **표 조각 줄(0095·0098)은 이번 최소 수정에서 뺌**
   - 줄 나누기·학습 데이터 문제라 재학습 과제로 따로 둡니다.
