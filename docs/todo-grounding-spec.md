## 1. 왜

- 상세 분석 입력에는 공고 본문이 없어서(`build_messages`), '지원 전 할 일' 두 줄이 대부분 "공고 원문에서 ○○를 확인합니다" 또는 "방학·서울과 대조합니다"였음
- 34건 손 판정(care-loop-spec §2.4): 67줄 중 근거 없음 18. 그중 10줄은 입력에 없는 장소·근무 기간을 찾게 함
- 원문 일부를 입력에 넣는 안(8(b))은 형식 기준 미달로 이번에 하지 않음. 그래서 후처리로 근거 없는 줄만 뺌

## 2. 규칙

`ground_report`의 todo 처리에 단계 하나를 더한다. 기존 처리(마감 지남 → 고정 문장, 미충족 → 지원서·근거 없는 일정 줄 빼기)를 먼저 하고, 그 결과가 기존 고정 문장('이번 모집은 지원 전에 할 일이 없습니다.')이면 건너뜀.

todo의 줄마다:

1. **일반 줄 빼기**: 아래 `GENERIC`에 걸리는 말(지시 동사, 학생 칩 말, 일반 명사, 조사)을 모두 지우고 공백을 정리했을 때, 남은 글자(한글·영문·숫자만 셈)가 2자 미만이면 뺀다
   - 예: "공고 원문에서 지원 마감일을 확인합니다." → 남는 말 없음 → 뺌
   - 예: "26학년도 12학점 신청 자격에 해당하는지 학사 정보로 확인합니다." → '26학년 12학점 학사 정보'가 남음 → 남김
2. **장소 줄 빼기**: 1을 통과한 줄이라도, 줄에 장소·이동 말(`PLACE_LINE`)이 있는데 입력 자료의 공고 부분(`build_messages`가 만든 user JSON의 "공고" 칸 전체)에 장소 정보(`PLACE_IN`)가 없으면 뺀다
3. 남는 줄이 없으면 todo는 고정 문장 **'공고 자료로는 지원 전 할 일을 정하기 어렵습니다.'**
4. 바꾼 내용은 기존처럼 `changes`에 남김(예: `{"todo": "ungrounded_dropped", "todo_dropped": 1}`)

정규식(저장된 답으로 시험한 그대로. 이름은 바꿔도 되지만 뜻은 지킴):

```python
GENERIC = re.compile(
    r"공고\s*원문|원문\s*공고|원문|공고|공지|상담센터|첨부\s*자료|"
    r"확인(?:해|하여|한|합니다|하고|한\s*뒤)?|대조(?:해|하여|합니다)?|판단합니다|정합니다|찾아|진행합니다|"
    r"해당하는지|맞는지|있는지|없는지|겹치는지|가능한지|가능성|가능\s*여부|여부|인지|"
    r"실제(?:로)?|구체적인|세부|전체|나머지|추가|본인(?:의)?|학생|함께|먼저|"
    r"방학(?:\s*일정|\s*중|\s*기간)?|학기\s*중|수업|서울(?:에서(?:의)?)?|경기도에서\s*열리는|이동(?:\s*경로|\s*시간|\s*일정)?|참석(?:할\s*수)?|참여(?:할\s*수)?|방문할\s*수|활동\s*범위|"
    r"가능한\s*시기|고른|"
    r"장소|위치|일정|기간|시기|날짜|시간|방법|절차|방식|대면|대상|자격|조건|요건|기준|범위|내용|활동|진행|모집|지원|신청|접수|마감일|"
    r"근무지|근무|부서|업무|프로그램|행사|대회|설명회|면접|특강|인턴십|"
    r"에서|을|를|이|가|은|는|와|과|의|도|로|으로|에|및|하고|하며|"
    r"합니다|입니다|있는|[.,·()'\"]"
)
PLACE_LINE = re.compile(r"장소|이동|참석|대면|근무지|위치|방문")
PLACE_IN = re.compile(r"장소|근무지|근무장소|온라인|비대면|대면|\d+\s*호|호텔|캠퍼스|본관|센터|[가-힣]+(?:시|구|군|도)\s")
```

- '서울'·'방학'은 시험 프로필의 칩 값이다. 운영에서는 학생이 고른 칩(가능한 시기·갈 수 있는 지역)의 한국어 이름을 같은 자리에 넣는다(`payload.PERIOD_CHIPS`·`REGION_CHIPS`의 값). '상관없음'은 넣지 않음
- 입력 자료를 `ground_report`에 넘겨야 하면 인자를 하나 더함(예: `material: str | None`). 서비스·하네스 점검 도구 양쪽에서 같은 값을 넘김
