# 카톡 공고 넘기기: 캡처 이미지 고르기 버튼 (하위 에이전트용)

- 작성: 2026-11-27, 팀장 승인(image_picker 추가)
- 기준: `origin/main` 최신, worktree `.claude/worktrees/share-image-picker`, 브랜치 `feat/share-image-picker`
- 커밋·PR·배포·Firestore 금지

## 배경

- 공식 알림톡은 카톡 공유 메뉴가 없음 → 실제 경로는 붙여넣기·캡처
- 지금 캡처는 갤러리 '공유 → 귀띔'으로만 들어옴. 앱 안에서 고를 수 없음

## 할 일

- `image_picker`(Flutter 공식, 무료) 추가. 다른 패키지 추가 금지
  - Android 13+ 시스템 사진 선택기 사용, 저장소 권한 추가하지 않음(필요하면 이유 보고)
- 저장함 '카톡 공고 넘기기'(`apps/mobile/lib/ui/share_flow.dart` 진입 영역)에 '캡처 이미지 고르기' 버튼
  - 기존 '복사한 글 붙여넣기' 옆이나 아래. `docs/ui-style.md` 따름
  - 고른 이미지는 공유로 받은 이미지와 같은 흐름: 기기 안 OCR → 확인 화면(수정·가림 미리보기) → 동의 → 보내기. `input`은 `share_image_ocr`
  - 고른 파일은 앱 캐시 사본으로 다루고 OCR 뒤 지움(`deleteShareFile`). 서버로 보내지 않음
  - 선택 취소면 아무것도 안 함. 글자를 못 읽으면 기존 안내 그대로
- 안내 한 줄 수정: "알림톡은 화면을 캡처한 뒤 '캡처 이미지 고르기'로 넘깁니다" 취지. 명사형·합쇼체(해요체 금지)
- `docs/decisions.md` D-058 아래 한 줄(또는 새 번호): image_picker 추가, 이유
- `docs/legal/privacy.md`: 변경 필요 여부만 확인(이미지는 기기 밖으로 안 나감)

## 추가 (2026-11-27, 팀장 실기기 확인 뒤)

실기기 캡처 1장 결과: 마감 12/18은 맞음. 제목이 상태 표시줄 시각 "8:54 ALIR)"로 잡힘. 카톡 화면 요소("← 명지전문대학 공지사항", "Ch+ 채널 추가", "알림톡 차단", "채널 홈 바로가기", ".l 88" 등)가 본문에 섞임. 제목 "2026학년도 동계방학 어학아카데미 / 안내"가 두 줄로 쪼개짐.

### A. 진입 단계 줄이기
- 홈(오늘 탭) 위쪽에 '카톡 공고 넘기기' 한 줄 카드: [캡처 고르기] [붙여넣기] 버튼 두 개. 한 번 눌러 바로 선택기·확인 화면
- 저장함 진입은 그대로 두되 홈과 같은 위젯 재사용
- 샘플 자료 모드·로그인 전에는 안 보임(기존 규칙)

### B. OCR 결과 정리 (기기 안, 확인 화면에 넣기 전)
- `MlkitTextOcr`가 `result.text` 대신 블록·줄 좌표를 써서 정리
  - 이미지 위쪽 상태 표시줄·카톡 상단 바 영역과 아래쪽 입력·메뉴 바 영역의 줄 제외(높이 비율 기준, 값은 실제 캡처로 정함)
  - 카톡 화면 요소 문구 제외: 채널 추가, 알림톡 차단, 채널 홈 바로가기, 메시지 메뉴, 시각만 있는 줄(`8:54` 등), 기호·숫자만 있는 짧은 줄
  - 같은 문단에서 줄바꿈으로 쪼개진 줄은 이어 붙이기(줄 간격·들여쓰기 기준). 특히 제목 다음 줄이 '안내'처럼 짧으면 합침
- 정리 함수는 순수 함수로 분리해 단위 테스트(합성 OCR 결과 줄 목록 + 좌표). 원본은 버리지 않고 확인 화면에서 '인식한 원문 그대로 보기'로 펼칠 수 있게 할지 판단해 보고
- 서버 제목 규칙(`title_of`)은 이번에 건드리지 않음. 앱 쪽 정리만으로 위 캡처에서 제목이 '2026학년도 동계방학 어학아카데미 안내'가 되는지 테스트로 확인

### C. 복사한 글 자동 제안 (2026-11-27 팀장 요청)
- 은행 앱의 '복사한 계좌번호 붙여넣기'처럼, 앱을 열거나 다시 앞으로 올 때 클립보드에 글이 있으면 홈 맨 위에 제안 카드
  - 문구 예: "복사한 알림톡을 불러올까요?" + 첫 줄 미리보기(1줄, 말줄임) + [불러오기] [닫기]. 명사형·합쇼체 기준에 맞게 다듬기(해요체 금지)
  - [불러오기] → 기존 붙여넣기 흐름(확인 화면, 가림 미리보기, 동의, 보내기). 자동으로 보내지 않음
- 언제 보일지
  - 먼저 `Clipboard.hasStrings()`로 있는지만 보고, 있을 때만 내용을 읽는다(Android 12+는 읽을 때 시스템 '붙여넣음' 알림이 뜸 → 앱 시작·다시 열기 때 한 번만)
  - 공고처럼 보일 때만: 20자 이상, 날짜·'까지'·모집·신청·안내 같은 말 중 하나, 기기 가리기 종류 판정(`kakaoKind`)이 개인 알림·잡음이 아님
  - 이미 넘긴 글·닫은 글은 다시 제안하지 않음: 가린 본문 해시를 기기에만 저장(SharedPreferences, 최근 20개)
- 클립보드 내용은 기기에서만 다루고, [불러오기] 전에는 서버로 보내지 않는다. 처리방침 변경 필요 여부 보고
- 샘플 모드·로그인 전에는 안 함
- 테스트: 클립보드·저장소 가짜 주입으로 제안 보임/안 보임(짧은 글, 개인 알림, 이미 닫은 글), 불러오기 → 확인 화면
- 에뮬레이터: `adb shell` 등으로 클립보드에 합성 공고를 넣고 앱 다시 열기 → 카드 → 확인 화면까지 캡처. 보내기 금지
