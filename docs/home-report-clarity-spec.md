## 2. A. 홈: 누를 곳이 보이게, 더 보기는 그 자리에서 펼치기

### A1. 줄 오른쪽 끝 화살표

- `_HomeLine`(마감 줄·아이콘 줄 모두) 오른쪽 끝에 `Icons.chevron_right_rounded` 20, 색 `faint`, 세로 가운데. 글 묶음과 간격 4
- 조건 상태 원은 지금처럼 제목 옆에 둠(화살표와 자리를 바꾸지 않음)
- 화살표는 화면 읽기에서 뺌(`ExcludeSemantics`). 줄 자체가 버튼으로 읽히는지 확인하고, 아니면 `Semantics(button: true)`를 더함
- 360 폭·글자 1.3배에서 제목 2줄 말줄임이 유지되는지 확인

### A2. '전체 N건 >'(달력으로 이동)을 없애고 카드 안에서 펼치기

- 구역 제목 오른쪽 글: 이번 주 마감은 늘 '앞으로 7일'(다음 마감은 지금처럼 '앞으로 2주'). `_ShowAll('전체 N건')`은 지움
- 줄 수(맞춤 5, 최신 모드 3)를 넘는 7일 안 후보가 있으면 카드 맨 아래에 펼침 줄을 둠
  - 접힌 상태: 'N건 더 보기' + `expand_more_rounded` 18. 펼친 상태: '접기' + `expand_less_rounded` 18
  - 글자 14/600 `sub`, 가운데 맞춤, 높이 48 이상, `InkWell` 반지름 12. 리포트 체크리스트의 '○개 더 보기'와 같은 모양(`report_screen.dart` `_CheckLineState` 참고)
  - 펼치면 7일 안 후보 전부가 같은 카드 안에서 기존 마감순으로 이어짐. 추가 줄도 마감 줄 모양(`dated: true`)으로 표시
  - 높이 변화는 220ms `Curves.easeOutCubic`(ui-style §4 '목록 높이 변화'), 애니메이션 줄이기면 0
- **N은 접힌 마감 카드에 아직 보이지 않는 7일 안 후보 수.** `buildHomeSections`에서 공고 ID로 중복을 제거한 7일 안 후보 전체를 기준으로 계산. 아래 '새 공고'에 보이는 후보도 N에 포함. N이 0이면 펼침 줄을 숨김
- **중복은 현재 화면에 보이는 줄을 기준으로 처리**(D-050). 접힌 상태에서는 기존 홈 구성을 사용. 펼친 동안에는 아래 구역에서 마감 카드와 같은 ID의 줄만 숨기고, 남은 줄은 원래 순서대로 표시. 빈 구역은 제목과 여백까지 숨김. 다시 접으면 아래 구역도 복원
  - 펼친 마감 줄에는 해당 공고의 '새 공고' 표시와 기존 마감 변경 문구를 적용. 같은 ID의 하단 마감 변경 카드도 그동안 숨김. 귀띔 말풍선 건수는 펼침 상태와 무관
- 펼친 상태는 홈 화면 상태로만 가짐(기기에 저장하지 않음). 당겨서 새로 고침·탭 이동에는 유지, 앱을 다시 켜면 접힘
- `HomeScreen.onShowCalendar`와 `main.dart`의 연결은 쓰는 곳이 없어지면 지움. 달력은 하단 탭으로 감
- '마감이 먼 맞춤 공고'의 '전체 보기 >'(공고 탭)는 그대로 둠

### A3. 하지 않는 것

- 날짜 블록·`Pill` 모양은 바꾸지 않음(A1 화살표로 누를 곳이 정해짐)
- 접힌 상태의 줄 수와 구역 순서, 귀띔 말풍선은 기존 규칙을 따름

## 3. B. 리포트: 맨 위에 결론, 체크리스트는 확인할 것부터

### B1. 결론 카드 (새 위젯, 예: `_Verdict`)

- 자리: 출처·게시일 줄 바로 아래, `_CaseCard` 위. 바깥 여백 `fromLTRB(20, 16, 20, 0)`
- 틀: `_CaseCard`와 같음(`card` 바탕, `line` 테두리 1, 반지름 16, 안쪽 여백 16/14)
- 줄 최대 3개. 줄마다 '아이콘 18 `muted` · 이름표 13/600 `sub`(폭 고정, 예: 44) · 값 15/600'. 줄 사이 10. 값은 두 줄까지(`keepAll`)

| 줄 | 이름표 | 값 | 값 색 | 없을 때 |
|---|---|---|---|---|
| 조건 | '조건' | 아래 표 | 아래 표 | 추천 정보 없이 연 공고(`recommendation == null`)는 줄을 두지 않음 |
| 마감 | '마감' | '12월 3일 17:00 마감 · D-8'. 날짜만 확인되면 '12월 3일 마감 · D-8'. 오늘이면 확인된 시각에 따라 '오늘 17:00 마감' 또는 '오늘 마감' | 7일 안이면 `urgent`, 아니면 `ink` | 마감일이 `null`이면 원문의 `deadlineNote`(예: '예산 소진 시까지')를 표시. 설명도 없으면 '마감일 미상'(`sub`) |
| 추천 | '추천' | `homeReason(...)`의 글('관심 분야', '관심·전공' 등) + ' 관련' | `accent` | 이유가 없으면 줄을 두지 않음 |

조건 줄의 값(판정은 서버 값 그대로, 앱에서 다시 판정하지 않음):

| `eligibilityStatus` | 값 | 색 |
|---|---|---|
| `met` | '조건 충족' | `accent` |
| `needs_check` | N이 1 이상이면 '확인 필요 N개'. 이름표가 있는 확인 줄이 있으면 '확인 필요 1개 · 학년'처럼 항목 이름을 최대 2개 표시. N이 0이면 '지원 조건 확인 필요' | `check` |
| `not_met` | '조건 미충족'. 미충족 항목 이름을 뒤에 ' · 학년'처럼 최대 2개 | `urgent` |

- N과 항목 이름은 `checklistRows(...)` 결과에서 셈(`CheckState.check`의 `count` 합, `field`가 있는 줄의 이름). 체크리스트 안내 문장의 개수와 같아야 함
- `eligibility.extractionComplete`가 `false`면 조건 줄 값 뒤에 덧붙이지 말고, 지금처럼 체크리스트 아래 안내 문장에 맡김. '지원 가능' 같은 단정하는 말은 쓰지 않음(SPEC 데이터 정확성 규칙)
- 모집 상태가 `closed` 또는 `removed`이면 마감 줄 하나에 `lifecycleLabel(...)`을 표시(`sub`). `unknown`은 모집 여부를 확인하지 못한 상태이므로 위 표를 적용해 제공된 조건 판정·추천 이유와 확인된 마감 정보를 표시
- 날짜·남은 날 글자는 새로 만들지 않고 `lib/ui/format.dart`·`case_view.dart`(`remainingText` 등)에 있는 것을 씀. 맞는 함수가 없으면 `format.dart`에 더하고 테스트를 붙임
- 지원 건의 '다음 할 일'은 결론 카드에 넣지 않음(바로 아래 `_CaseCard`가 보임)
- 화면 읽기: 카드 하나를 '조건 확인 필요 2개, 12월 3일 마감 D-8, 관심 분야 관련'처럼 한 덩어리로 읽음
- 제목 위 칩의 '모집 중 · D-N'은 그대로 둠(위 막대에 가려지기 전 첫 화면 정보)

### B2. 체크리스트: 확인할 것 먼저, 충족은 접기

- 줄 순서를 상태별로 바꿈: 미충족 → 확인 필요 → 충족 → 안내(`info`, 우대 사항 포함). 같은 상태 안에서는 지금 순서 유지. 정렬은 `checklistRows`의 `groupCheckRows` 뒤에 함
- 충족 줄 접기: 미충족·확인 필요 줄이 하나라도 있고 충족 줄이 2개 이상이면, 충족 줄들을 '충족 N개' 한 줄(체크 표시 + 14/600 `sub` + `expand_more_rounded` 18)로 접고 누르면 펼침. 펼치면 '접기'
  - 충족 줄만 있거나 충족이 1개면 접지 않음
- 안내 문장('조건 2개 충족. 3개는 직접 확인해 주세요.')과 배지는 그대로

### B3. 순서

바뀐 순서: 칩 → 제목 → 출처·게시일 → **결론 카드** → `_CaseCard` → `_SummaryBubble` → `_StaleBox` → `_ChangeBanner` → `NoticePoster` → `_Checklist` → `AnalysisAction` → **`_Schedule` → `_Reasons`** → `_Related`

- 바뀌는 것은 결론 카드 추가와 일정·추천 이유의 자리 맞바꿈뿐. 포스터 자리(2026-11-24 결정)는 그대로
- `_Reasons`의 안내 문장('합격 가능성과는 관계없습니다.' 등)은 지우지 않음

### B4. 하지 않는 것

- 요약 말풍선·상세 분석 버튼·일정·관련 공지의 내용과 모양
- 상세 분석 결과 화면(`agent_flow.dart`)
- 서버 응답·판정 규칙

## 5. 검증과 완료 기준

- 위젯 테스트(`apps/mobile/test/`)
  - 홈(맞춤): 7일 안 후보 8건 중 마감순 6~8번째가 아래 '새 공고' 3건인 사례. 처음에는 마감 5줄과 '3건 더 보기'. 펼치면 마감 카드 안에 8건이 순서대로 보이고 마지막 3줄에 '새 공고' 표시가 붙음. 아래 '새 공고' 구역은 숨고, '접기'를 누르면 원래 두 구역이 복원됨. 후보 5건이면 펼침 줄 없음
  - 홈(마감 변경): 추가로 펼칠 후보에 하단 마감 변경 카드가 있는 저장 공고 포함. 펼치면 변경 문구는 해당 줄에 보이고 겹치는 카드는 숨음. 접으면 카드 복원. 두 상태에서 말풍선 건수 동일
  - 홈(최신): 후보 4건이면 3줄과 '1건 더 보기' → 펼치면 4줄. 후보 3건이면 펼침 줄 없음. 두 모드 모두 '전체 N건'은 표시하지 않음
  - 리포트(조건): `met`·`not_met`·추천 정보 없음 각각의 표시 확인. `needs_check`에서 N이 양수면 체크리스트와 같은 건수, 조건을 찾지 못해 N이 0이면 '지원 조건 확인 필요' 표시
  - 리포트(모집 상태): `unknown`이며 조건 판정과 추천 이유가 있는 공고는 두 줄 모두 표시. 마감 날짜가 없고 원문 설명이 있으면 '예산 소진 시까지' 등 그 설명을 표시하고, 설명도 없으면 '마감일 미상'. `closed`와 `removed`는 각각 '마감'과 '삭제된 공고' 값 한 줄만 표시
  - 리포트(오늘 마감): 17:00이 확인됐으면 '오늘 17:00 마감', 날짜만 확인됐으면 '오늘 마감'
  - 체크리스트: 상태별 순서, 충족 접기 조건 3가지(접힘 / 충족만 / 충족 1개)
  - `text_scale_test.dart`: 360 폭·글자 2배에서 홈(펼친 상태)·리포트(결론 카드)가 넘치지 않음
  - '전체 N건'·`onShowCalendar`를 쓰던 기존 테스트는 새 동작에 맞게 고침(지우지 않음)
- 실행: `apps/mobile`에서 `flutter analyze`(오류 0), `flutter test`(전체 통과, 현재 459개에서 늘어남)
- 화면 확인: 에뮬레이터에서 라이트·다크 각각 홈(접힘·펼침), 리포트(확인 필요 공고, 충족 공고, 저장한 공고) 캡처를 `data/local/`에 남기고 PR에 경로를 적음. 실제 공고로 보는 방법은 `docs/handoff.md`의 로컬 서버 절 참고
- 앱 문구는 명사형·합쇼체(해요체 금지, D-022), 색은 `context.gw` 토큰만, 새 글자 크기를 만들지 않음

## 7. 작업 방식

- 메인 체크아웃에는 팀장 작업이 있을 수 있음. `git status`로 확인한 뒤 새 worktree(`.claude/worktrees/home-report-clarity`)에서 `origin/main` 기준으로 브랜치를 만듦. 끝난 뒤에도 worktree는 지우지 않음
- 커밋 메시지는 짧고 담백하게. `Co-Authored-By`·`Generated with` 꼬리말을 붙이지 않음
- PR 본문은 변경점·실행한 검증(명령과 실제 결과)·남은 문제만 짧게. 실행하지 못한 검증은 '미실행'과 사유
- 비밀값·`google-services.json`·`.env`는 커밋하지 않음(AGENTS.md §4)

## 8. 고친 뒤 확인할 것 (팀장)

- 12/1~2 사용자 테스트에서 같은 과제를 다시 줌
  - 홈: "이번 주에 마감되는 공고를 전부 보여 주세요" → 마감 카드 안에서 전부 찾는지. 이어 "그중 하나의 자세한 내용을 보여 주세요" → 공고 줄을 눌러 리포트를 여는지
  - 리포트: "이 공고에 지원할 수 있는지, 언제까지인지 말해 주세요" → 첫 화면에서 답하는지, 걸린 시간
- 이 명세의 방향은 2명의 말을 코드와 맞춰 본 추정임. 테스트에서 다른 곳을 누르면 그 기록을 우선함
