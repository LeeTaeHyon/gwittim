# 공고 분석 자체 모델 (D-042)

공고 본문에서 "신청 마감이 적힌 줄", "지원 자격·우대 조건 줄", "재학·학교·학년 조건 줄"을 골라내는 작은 모델이다.
이 문서는 모델이 무엇을 하고, 어떻게 만들었고, 운영에서 어떻게 쓰이는지를 처음 보는 사람도 따라올 수 있게 적는다.

- 코드: `backend/analysis/extract_model.py` (추론·합치기), 시험 `backend/analysis/tests/test_extract_model.py`
- 학습 자료·코드: 팀장 PC `data/local/extract_distill/` (저장소 밖, 개인정보가 섞인 원문 포함)
- 가중치: 배치 PC `<data-dir>/models/extract-v1/` (225MB, 저장소 밖)

## 1. 풀려는 문제

공고에서 학생에게 필요한 정보는 대부분 몇 줄에 몰려 있다.

```
[합성 예] 2026 겨울방학 해외 연수 참가자 모집
신청기간: 2026.11.02.(월) ~ 2026.11.13.(금)      ← 마감 줄
지원자격: 본교 재학생 (휴학생 제외)              ← 학교·재학 조건 줄
직전 학기 평점 3.0 이상                          ← 자격 줄 (프로필로 판정 못 함)
토익 700점 이상 우대                             ← 우대 줄
```

규칙 분석기(`rules.py`)는 '신청기간', '재학생' 같은 낱말로 이 줄들을 찾는다. 낱말이 조금만 달라도 놓친다
("늦어도 11월 9일 17시 30분 전까지 보내 주세요"). 그래서 규칙 뒤에 Gemma(12B 언어 모델)를 붙여 빈 곳을 메웠는데,
Gemma는 느리고(공고당 약 4.5초, GPU 필요) 없는 마감을 만들어 내는 일이 잦았다.

이 모델은 문제를 **줄 고르기**로 바꾼다. 날짜를 직접 쓰거나 조건 값을 만들지 않고, "이 줄이 마감 줄인가?"만 답한다.
고른 줄의 날짜는 기존 날짜 파서가 읽는다. 그래서 근거가 늘 원문 한 줄이고, 원문에 없는 문구가 나올 수 없다.

## 2. 꼬리표

줄마다 아래 11개 꼬리표를 **동시에** 붙일 수 있다(다중 꼬리표). 한 줄이 "재학생, 2학년"이면 `enr_enrolled`와 `grade_2`가 함께 켜진다.

| 꼬리표 | 뜻 | 운영에서 쓰는 곳 |
|---|---|---|
| `deadline` | 신청 마감 근거 줄 | 신청 마감 (`application_deadline`) |
| `qual` / `pref` | 프로필로 판정 못 하는 자격 / 우대 조건 | 미해석 조건 (직접 확인) |
| `uni_mjc` | 본교생 조건 | `university_id` 조건 |
| `enr_enrolled` / `enr_on_leave` / `enr_graduated` | 재학 / 휴학 / 졸업 허용 | `enrollment_status` 조건 |
| `grade_1` ~ `grade_4` | 학년 조건 | `grade` 조건 |

공고 단위로 "누구나 지원 가능"도 맞히게 했지만 시험 점수가 0이라 운영에서 쓰지 않는다.

## 3. 학습 데이터

1. 게시판 공고와 알림톡 801건을 모은다 (`label_run.py pool`). 본문은 앞 일부만.
2. DeepSeek V4.1 Flash가 공고마다 마감·조건·근거 문구를 JSON으로 답한다 (초벌 라벨). 시범 30건은 Claude가 직접 라벨, 그중 20건은 사람이 확인.
3. Claude가 초벌을 검수했다. 여러 프로그램이 묶여 정답이 하나로 정해지지 않는 공고 70건은 뺐다.
4. 라벨의 근거 문구가 들어 있는 줄을 찾아 꼬리표를 붙인다 (`build_data.py`). 연락처(전화·이메일)는 지운다.
5. 게시판별로 섞어 학습 567건 / 검증 70건 / 시험 94건으로 나눈다. 시범 30건은 모두 시험에 넣었다.

정답이 사람 라벨이 아니라 **상위 언어 모델 라벨**이라는 점이 중요하다. 이 모델의 점수는 "사람과 얼마나 같은가"가 아니라
"상위 모델의 판단을 얼마나 따라 하는가"다(지식 증류). 팀장 판단: 상위 모델과 같을수록 좋다.

## 4. 모델 구조

```
줄들 ──토큰화──▶ [CLS] 줄1 [SEP] 줄2 [SEP] 줄3 [SEP] ... (최대 512토큰)
                         │
                 KoELECTRA-base v3 (한국어 사전학습 인코더, 1억 1천만 매개변수)
                         │ 토큰마다 768차원 벡터
                 줄마다 그 줄 토큰 벡터의 평균 ──▶ 선형층 ──▶ 11개 확률 (시그모이드)
                 [CLS] 벡터 ──▶ 선형층 ──▶ "누구나" 확률
```

- **왜 줄을 한 번에 넣나**: "신청기간"이라는 낱말이 없는 줄도 앞뒤 줄(제목, '3. 접수' 같은 소제목)을 보면 마감 줄인지 알 수 있다. 줄을 따로따로 넣으면 이 문맥을 잃는다.
- **긴 공고**: 512토큰에 다 안 들어가면 창 여러 개로 나누고, 창 사이에 2줄을 겹친다. 겹친 줄은 창별 확률을 평균한다. 한 줄은 최대 96토큰까지만 쓴다.
- **시그모이드(소프트맥스 아님)**: 꼬리표가 서로 배타적이지 않아서 각각 0~1 확률을 따로 낸다.

## 5. 학습

- 손실: 꼬리표마다 이진 교차 엔트로피. 드문 꼬리표(학년·휴학 등)는 놓치기 쉬워서 양성 손실에 가중치를 준다
  (음성 수 / 양성 수의 제곱근, 최대 30. 예: deadline 6.4, grade_2 30).
- AdamW, 학습률 5e-5, 배치 8, 앞 10% 워밍업 후 선형 감소, 최대 15에폭, 검증 점수가 4에폭 동안 안 오르면 멈춤.
- 에폭마다 검증 세트로 **꼬리표별 문턱**을 고른다(0.05~0.95 중 F1이 가장 높은 값). 예: deadline 0.95, pref 0.45.
  마감 문턱이 높은 이유: 마감 줄을 하나만 고르므로 확실할 때만 고르게 한다.
- 가장 좋았던 에폭(14)의 가중치와 문턱을 저장한다. RTX 5070에서 약 2분.

## 6. 평가

시험 94건은 학습·문턱 고르기에 쓰지 않은 공고다. 줄 단위 F1(정밀도와 재현율의 조화 평균):

| 꼬리표 | 시험 F1 | 정답 줄 수 |
|---|---|---|
| deadline | 0.81 | 44 |
| qual | 0.69 | 90 |
| pref | 0.63 | 18 |
| enr_enrolled | 0.78 | 35 |
| uni_mjc | 0.47 | 9 |
| 휴학·졸업·학년 | 판단 불가 | 0~4 |

운영에서 중요한 건 줄 점수보다 **공고 단위 결과**다. 같은 94건에서 규칙, 규칙+Gemma(이전 운영), 이번 분석기를 비교했다
(`data/local/extract_distill/compare.py`). 표는 [decisions.md](decisions.md) D-042.

- 마감: 84건 맞음, 틀리거나 없는 마감을 만든 것 1건 (규칙+Gemma 77건, 15건).
- 기타 조건: 정답 조건의 82%를 찾음 (규칙+Gemma 68%).
- 재학·학교 조건: 규칙과 비슷하다. 조건이 없는 공지에 '재학생'을 붙이는 경우가 몇 건 늘었다.

## 7. 운영에서 합치는 방식

규칙 분석을 먼저 하고, 모델 결과로 항목마다 다르게 고친다. 각 방식은 94건에서 여러 조합을 비교해 골랐다.

| 항목 | 방식 | 이유 |
|---|---|---|
| 신청 마감 | 모델만. 못 고르면 미상 | 규칙으로 메우면 맞는 것만큼 틀린 마감도 늘었다. 틀린 마감은 열린 공고를 닫힌 것으로 보이게 한다 |
| 재학·학년·학교 | 규칙 먼저, 빈 필드만 모델 | 학교 조건은 규칙이 더 잘 찾는다 |
| 기타 자격·우대 | 규칙 + 모델 합침 | 놓친 조건은 판정을 뒤집는다. 더 묻는 쪽이 낫다 |
| 누구를 빼는 줄 | 조건으로 만들지 않음 | D-023. '휴학생 제외'를 '재학생 허용'으로 읽으면 틀릴 수 있다 |

- 연도 없는 날짜("11월 15일(일) 23:59까지")는 게시·발송일 근처의 해로 읽는다 (알림톡 날짜 규칙, D-019).
- 모델 입력은 연락처를 지운 줄(학습 때와 같게), 근거로 남기는 건 원문 줄이다.
- 모델을 불러오지 못하거나 예측이 실패하면 그 공고는 규칙 분석 결과와 규칙 버전으로 게시한다. 버전이 달라 다음 배치에서 다시 분석된다.
- Gemma는 요약(`summary`)과 알림톡의 애매한 분류만 맡는다. Ollama가 없으면 요약 없이 게시한다.

## 8. 실행

```powershell
uv sync --group extract                         # torch(CPU)·transformers 설치 (배치 PC 한 번)
# 가중치 5개 파일을 <data-dir>\models\extract-v1\ 에 둔다:
#   meta.json, config.json, tokenizer.json, tokenizer_config.json, model.safetensors
uv run --group extract python -m backend.collectors.mjc_www --pages 1 --max-items 3 --no-llm   # 빠른 확인
```

- 정기 배치(`scripts/run_batch.ps1`)는 `--group extract`로 돈다. 가중치 폴더가 없으면 예전처럼 규칙 + Gemma 추출.
- 끄려면 `--no-extract-model`. 다른 폴더는 `--extract-model <폴더>`.
- 배치 요약 JSON의 `extract_model`에 분석 버전, 모델로 분석한 수, 실패해 규칙만 쓴 수가 나온다.
- 이 PC(RX 9070)는 CUDA가 없어 학습은 못 하고 CPU 추론만 한다. 94건에 약 12초.

## 9. 오류 분석에서 배운 것 (2026-11-18)

시험·검증 세트에서 틀린 마감을 하나씩 보니 대부분 **모델은 맞는 줄을 골랐다**.

- 날짜 파서가 범위 끝을 못 읽어 시작일을 마감으로 썼다: `'25. 11. 20.(목) 9시 ~ '25. 12. 26.(금)`(생략 부호),
  `2025.6.30.~ 9.19.(9.19까지…)`(괄호 안이 요일이 아님), `2024. 9. 2.(월) ~ 20.(금)`(끝에 일만), `\~`(마크다운 흔적),
  `…5월 22일 금요일 9시부터 6월 22일 월요일 18시까지`(문장형). 요일이 빠진 `26.10.16.()`는 아예 못 읽었다.
  → `dates.py`를 고쳐 틀린 마감이 검증 4→0건, 시험 2→0건이 됐다. 규칙 분석도 같은 파서라 함께 좋아졌다.
- 맞는 줄인데 확률이 문턱(0.95)을 조금 못 넘은 경우가 시험에 5건 있다. 문턱을 0.8로 내리면 시험 점수는 오르지만
  검증 세트에서는 0.95가 가장 좋았다. 문턱은 검증 세트로만 고른다. 시험 세트로 고르면 시험 점수가 더는 '처음 보는 공고'
  점수가 아니게 된다(과적합).
- 기타 조건에서 틀린 것처럼 보이는 줄의 상당수는 참고 라벨이 일관되지 않거나(장학 공고의 지원 비율 설명을 어떤 공고는 넣고
  어떤 공고는 뺌), 같은 문장인데 끝의 `\`·앞의 `-` 때문에 다르게 비교된 경우다. 규칙 필터를 씌워 보았지만 검증 세트에서
  진짜 조건을 더 많이 버려 넣지 않았다. 라벨 기준을 정해 다시 검수하는 것이 먼저다.

## 10. 다시 학습할 때

1. 라벨을 늘리거나 고친다 (`labels_v1.json`). 특히 학년·휴학·졸업 조건 공고가 부족하다.
2. `python build_data.py` → `bundle/data.jsonl`, 학습 묶음을 GPU PC로 보내 `python train.py`.
3. 받은 `out/`을 `python verify.py out` 으로 이 PC에서 다시 예측해 점수가 같은지 본다.
4. `compare.py`로 이전 가중치와 공고 단위 비교 → 나아졌으면 `meta.json`에 `"model_version": "extract-v2"`를 넣고 배치 PC의 `models/`에 둔다.
   분석 버전이 바뀌어 다음 배치에서 전체 재분석된다.

## 11. 한계

- 학습 데이터가 명지전문대 게시판·알림톡뿐이다. 다른 학교·외부 공모전 공고에서는 점수를 모른다.
- 휴학·졸업·학년 조건은 학습 예가 수십 건이라 믿기 어렵다. 규칙이 먼저 찾는 구조라 영향은 작다.
- 정답이 상위 모델 라벨이라, 상위 모델이 틀린 곳은 이 모델도 같이 틀린다.
- 첨부 파일·포스터 이미지 속 조건은 보지 못한다(규칙 분석과 같다).
