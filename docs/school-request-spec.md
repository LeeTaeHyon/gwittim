## 2. 학교 고르기

- 프로필 학교 선택: 지원 학교(명지·숭의) / 목록에 없는 학교 / 선택 안 함 (#125 구조 유지)
- '목록에 없는 학교'를 고르면 이어서 **전국 대학 목록에서 검색해 선택**(선택 사항, 건너뛸 수 있음)
  - 자유 입력은 받지 않는다(처리방침 "자유 입력 없음" 유지)
  - 목록에 학교가 없으면 '찾는 학교 없음'으로 끝낸다
- 전국 대학 목록(`school_directory`)
  - 학교 이름, 학교 코드, 홈페이지 주소만 둔다. 지원 학교 사전(`universities`)과는 별도
  - 출처: 공공데이터(대학 목록) 중 이용 조건이 확인된 것. **어떤 자료를 쓸지 미정**(§11)
  - 홈페이지 주소는 이 목록에 있는 값만 쓴다. 사용자가 주소를 입력하는 경로는 두지 않는다(서버가 임의 주소를 열지 않게)

## 3. 지원 요청과 robots 즉시 판정

### 3.1 흐름

1. 학생이 목록에서 학교를 고르면 앱이 `POST /v1/school-requests` `{school_id}`
2. 서버가 그 학교 홈페이지의 `robots.txt`를 한 번 읽는다(수집용 요청기 `http_polite`, GwittimBot, 시간 제한)
3. 판정
   - 사이트 전체(`/`)가 GwittimBot 또는 모든 봇에 막혀 있음 → `unavailable` (사유 `robots`)
   - robots를 읽지 못함(없음·오류) 또는 막히지 않음 → `reviewing`
   - 이 단계에서는 게시판 주소를 모르므로 "게시판 경로만 막힘"은 판정하지 않는다. 그 판단은 §4 도구와 사람이 한다
4. 같은 학교의 robots 결과는 7일 동안 다시 읽지 않는다(학교 사이트 부담)

### 3.2 상태 값

| 값 | 앱 표시 | 누가 바꾸나 |
|---|---|---|
| `reviewing` | 검토 중 | 서버(요청 때) |
| `unavailable` + 사유 `robots` | 지원 불가 · 학교 사이트가 자동 수집을 허용하지 않음 | 서버(요청 때) |
| `unavailable` + 사유 `terms` / `login` / `other` | 지원 불가 · 사유 한 줄 | **팀장이 스크립트로 수동 변경** |
| `supported` | 지원 중 | **팀장이 학교 팩을 추가한 뒤 수동 변경** |

- 승인 화면은 만들지 않는다. 수동 변경은 `scripts/` 아래 명령 하나(Firestore 문서 갱신)로 한다
- `supported`가 되면 학생은 프로필에서 그 학교를 지원 학교로 다시 고른다(자동 전환하지 않음)

### 3.3 저장

- `school_requests/{school_id}`: 상태, 사유, robots 확인 시각, 요청 수
  - 누가 요청했는지(사용자 ID 목록)는 저장하지 않는다. 학교별 요청 수만 센다
- 프로필: `requested_school_id`(선택). 학생 화면의 상태는 이 값으로 `school_requests`를 찾아 보여 준다
- 사용자당 요청 학교는 하나. 바꾸면 이전 요청 수는 줄이지 않는다(수요 신호용 근사치)

### 3.4 오류·남용

- 같은 사용자의 요청은 하루 5회까지(학교 바꾸기 포함)
- robots 요청 실패는 `reviewing`으로 두고 사용자에게 오류를 보이지 않는다
- 로그: 학교 코드, 판정, 소요 시간만. 사용자 ID와 robots 원문은 남기지 않는다

## 4. 약관 1차 읽기 도구 (팀장용)

- `tools/school_terms_check.py <school_id>`: 팀장 PC에서만 실행. 서버·앱에 붙이지 않는다
- 하는 일
  1. robots.txt 전체를 읽어 게시판 후보 경로가 막혔는지 표시
  2. 홈페이지 하단 링크에서 '이용약관' 페이지를 찾아 본문을 가져옴(없으면 "약관 없음")
  3. OpenCode 구독 LLM(DeepSeek V4.1 Flash, 도구 전부 끔 — #126과 같은 설정)이 약관을 읽고 D-038 기준 조항을 원문 그대로 뽑아 표시
     - 이용자 전체에 자동 접근·수집 또는 복제를 금지하는 조항
     - 회원에게만 걸린 조항(수집 봇에는 적용 안 함으로 분류)
     - 상업 이용 금지(귀띔은 무료·광고 없음이라 참고로만)
  4. 결과를 `data/local/school_terms/<school_id>.md`(git 제외)로 저장
- 상태를 바꾸지 않는다. "가능" 결론을 내지 않고 근거 조항만 보인다. 판단은 팀장
- 요청 사이 3초, 학교당 요청 10회 상한

## 5. 숭의여대 학교 팩 (수동 1곳)

### 5.1 왜 숭의인가 (2026-11-22 팀장 확정)

- 공지 본문이 대부분 텍스트(상세 15건 중 10건이 100자 이상). 배화는 15건 모두 본문이 포스터 이미지라 이미지 읽기(OCR)가 먼저 필요
- 목록이 서버에서 그린 HTML 표라 어댑터가 단순
- 같은 CMS를 쓰는 대학 후보가 있음(숙명 등, 미확인) → 어댑터 재사용 가능성

### 5.2 들어가는 것

| 재료 | 내용 |
|---|---|
| 지원 학교 사전 | `universities`에 `sewu` 숭의여자대학교 |
| 학과 사전 | `majors`에 `sewu.*`(메인 메뉴의 학과 약 22개, 실제 목록은 구현 때 확인) |
| 수집기 | `backend/collectors/sewu_www`: 공지사항 게시판 1개부터. 분류(공통·교무학사·장학대출 등)는 `source_fields`에 보존 |
| 출처 설정 | `backend/sources.py`에 `sewu_www_notice`(university_id `sewu`) |
| 예의 | robots 준수, 요청 사이 3초, 실행당 상한, 하루 2회(최소 3시간 간격 기준 충족) |
| robots 제약 | 본문 이미지 `/_attach/`는 robots가 막음 → 받지 않음. 포스터에만 있는 내용은 "원문 확인"으로 안내 |
| 분석 | 기존 분석·분류를 그대로 사용. 학과 키워드 규칙은 명지 규칙 중 같은 분야만 재사용, 나머지 학과 조건은 `unresolved_conditions`로 둔다 |
| 학과 통계 | 넣지 않음(숭의 학생에게 '졸업생 진로 추천' 없음) |
| 알림톡 | 넣지 않음 |

### 5.3 추천 규칙 변경

- 지금: `unlisted` 학생에게만 학교 출처 공지를 숨김(rank-0.7)
- 변경: **학교 출처 공지는 출처 학교와 프로필 학교가 같은 학생에게만** 보인다. 교외 공고는 모두에게
  - 명지 학생 → 명지 공지 + 교외, 숭의 학생 → 숭의 공지 + 교외, `unlisted` → 교외만
  - 학교 선택 안 함(null) → **교외만** (2026-11-22 팀장 결정)
    - 지금은 null 학생에게 명지 공지가 보인다(SPEC §6, #125). 이 규칙이 바뀌므로 SPEC §6도 같은 PR에서 고친다
    - 학교를 고르지 않은 기존 사용자는 명지 공지가 사라진다. 홈·공고 탭에 "학교를 고르면 학교 공지도 볼 수 있습니다." 한 줄 안내
- 공고 탭 검색에도 같은 규칙. `RANKING_VERSION` 올림

### 5.4 앱

- 학교 선택에 숭의여대 추가, 숭의 고르면 숭의 학과 목록
- 출처 이름: '숭의여대 공지'
- 화면 구조는 그대로(새 화면 없음, §6의 요청 상태 줄만 추가)

### 5.5 정기 배치

- `scripts/run_batch.ps1`: 명지 게시판 다음, 교외 수집 앞에 숭의 수집 단계 추가. `-NoSewu`로 끔. 실패해도 배치는 이어감
- 완료 알림에 '숭의 게시 N'
- 적용하려면 `Gwittim-batch` 갱신(팀장 PC 작업 스케줄러 그대로)

### 5.6 검증

- 숭의 공고 표본 20건 사람 채점: 카테고리, 마감일, 지원 조건(명지에서 만든 분석이 다른 학교에서 얼마나 맞는지)
- #126 도구로 숭의 목록 페이지도 시험(어댑터 정답과 비교)
- 정기 배치 2회 이상 실제 실행 확인(게시 건수, 오류 0)

## 6. 화면·문구 (해요체 금지, 명사형·합쇼체)

| 위치 | 문구 |
|---|---|
| 학교 검색 안내 | 목록에 없는 학교라면 학교를 골라 지원을 요청할 수 있습니다. |
| 요청 직후 · 검토 중 | 지원 요청 접수 · 검토 중. 지원이 시작되면 이 화면에 표시됩니다. |

| 지원 불가 · 기타 | 지원 불가 · (사유 한 줄) |

## 8. 처리방침·이용 허락

- 처리방침 1장 받는 정보에 '지원을 요청한 학교(목록에서 선택, 선택 사항)' 추가
- 숭의 공고는 공개 게시물만, 명지와 같은 원칙(작성자 IP 등 개인정보 필드 버림)
- **이용 허락**: 숭의는 이용약관 페이지가 없어 명지와 같은 상태(수집·재표시 허락 미확인). 앵커사업단(대회 주최) 경로로 허락을 요청할지 팀장 결정(§11)
  - 숭의 robots는 AI 봇 다수를 전체 차단한다. 우리 봇 이름은 해당하지 않지만, 맞춤 에이전트가 공고 내용을 외부 LLM(DeepSeek)에 보낼 수 있음을 허락 요청 때 밝힌다

| S9 | 상태 수동 변경 스크립트 | `reviewing → supported/unavailable` 변경, 사유 기록 |
| S10 | 약관 1차 읽기 도구 | 명지·숭의·배화로 실행해 보고서 생성, 상태를 바꾸지 않음 테스트 |

- 순서: S1 → (S2·S3·S4 → S5·S6) / (S7 → S8·S9) / S10은 언제든
- 숭의(S2~S6)가 먼저. 시간이 모자라면 S7~S9를 줄이고 S10 보고서만 보고서에 싣는다

## 11. 팀장이 정할 것

### 정한 것

| 항목 | 결정 | 날짜 |
|---|---|---|
| 두 번째 학교 | 숭의여자대학교(`sewu`)로 확정. 배화는 포스터 읽기가 먼저라 로드맵(§9) | 2026-11-22 |
| 학교 선택 안 함(null) 학생 | 교외 공고만 보임(학교 공지는 같은 학교 학생에게만). §5.3 | 2026-11-22 |

### 남은 것

1. 숭의·배화에 앵커사업단 경로로 이용 허락을 요청할지, 요청 전에 수집을 시작할지
2. 전국 대학 목록 자료(공공데이터 중 무엇을 쓸지, 이용 조건)
3. 요청 상태 문구(§6) 확정

## 12. 발표·보고서에서 쓰는 표현

- 쓸 수 있는 것(구현 후): "두 번째 학교(숭의여대)를 학교 팩으로 추가해 정기 수집 중", "목록에 없는 학교 학생은 지원을 요청할 수 있고, 학교 사이트의 robots 규칙을 바로 확인한다", "약관은 LLM이 1차로 근거 조항을 찾고 사람이 판단한다"
- 쓰지 않는 것: "요청하면 자동으로 학교가 추가된다", "어느 학교든 지원", 승인 화면·자동 생성 화면을 실제 기능처럼 보이는 목업
- 로드맵은 항상 "다음 단계"로 구분해 적는다
