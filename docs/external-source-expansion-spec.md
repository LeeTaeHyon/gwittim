# 교외 공고 수집 확대 명세 (하위 에이전트용)

- 작성: 2026-11-26 (11/26 멘토링 2번 과제, 12/3 미팅 전 목표)
- 상태: 팀장 결정 반영, 구현 전
- 기준 브랜치: `origin/main` 최신 (작성 시점 `5650146`). 새 worktree `.claude/worktrees/external-expand`, 브랜치 `feat/external-expand`
- 커밋·PR·배포·Firestore 쓰기 금지. 실제 사이트 수집 시험은 로컬 사본으로만

## 1. 배경

- 지금 교외 출처는 위비티·콘테스트코리아 공모전뿐(D-038 1차, D-048 중복 묶기)
- D-038에서 링커리어·씽굿·올콘·씽유는 이미 '수집' 분류(이용자 조항에 명시적 금지 없음). 1차 구현에서 미뤘던 것을 이번에 넣는다

## 2. 팀장 결정 (2026-11-26)

- 새 출처도 **운영 게시까지** 한다 (정기 배치에 넣어 하루 2번)
- 종류: **공모전 + 대외활동**. 인턴·채용 메뉴는 넣지 않음
- 그 밖의 동작 규칙은 D-038 그대로(robots, 3초 간격, 실행당 상한, 429·403 멈춤, `GwittimBot`, 운영사 요청 시 즉시 중단·삭제)

## 3. 출처와 순서

| 순서 | 출처·메뉴 | 비고 |
|---|---|---|
| 1 | 링커리어 공모전 | 2026-11-16 접근 시험 목록 링크 96개 |
| 2 | 링커리어 대외활동 | |
| 3 | 위비티 대외활동 | 기존 어댑터 확장. 11/23 기록: 검색 주소로는 결과 없음 → 목록 메뉴 주소 확인 |
| 4 | 씽굿 공모전 | 링크 33개, 첨부·로그인 경로는 robots 차단 |
| 5 | 올콘·씽유 | 조사만. 목록이 자바스크립트라 링크 0개. 헤드리스 브라우저 없이 HTML·페이지에 박힌 JSON으로 읽을 수 있을 때만 구현, 아니면 사유 보고. 씽유 `/contest/search.asp`는 robots 차단 |

- 시간이 모자라면 위 순서대로 끊고 남은 것을 보고
- 구현 전 출처마다 robots.txt·약관을 다시 읽는다. 이용자 전체에 걸린 자동 접근·복제 금지가 새로 생겼으면 그 출처는 멈추고 보고
- 링커리어는 Next.js 사이트: 상세·목록 HTML 안의 서버 렌더 내용이나 `__NEXT_DATA__` JSON을 쓴다. 내부 API(GraphQL 등)를 직접 부르는 것은 robots가 그 경로를 허용하고 HTML로 안 될 때만, 보고에 명시
- 로그인 필요 페이지는 열지 않는다

## 4. 구현

- 어댑터: `backend/collectors/<출처>/` (`adapter.py`·`parser.py`·`__main__.py`·`tests/`), 위비티·콘테스트코리아 구조 그대로
  - `ListDetailSource` + `collect_list_detail`, `http_polite`, `mask_contacts`, `audience` 재사용
  - 사이트가 마감 표시한 공고는 상세를 열지 않음. 응모 대상이 초·중·고·청소년뿐이면 제외(D-038)
  - 상단 표 정보(분야·대상·주최·접수 기간·혜택)는 본문 첫머리 '이름: 값' 줄로 (위비티 방식)
  - 주최 측 공식 페이지 주소는 `source_fields.official_url`에만. 따라가지 않음
- `backend/sources.py`: 출처별 `source_id`(예: `linkareer_contest`, `linkareer_activity`, `wevity_activity`, `thinkgood_contest`), 이름, 시간대 null(D-038과 같은 근거)
- 분류: 대외활동 공고가 전부 '공모전'으로 붙지 않는지 확인. 카테고리 사전(`contracts/dictionaries/categories.json`)의 기존 코드만 사용, 새 코드 추가 금지. 규칙 분석으로 안 되면 출처·메뉴별 기본 카테고리를 어댑터에서 넘기는 방식 허용(근거를 주석·결정 기록에)
- 중복(D-048): `backend/analysis/external_match.py` 출처 우선순위를 위비티 > 콘테스트코리아 > 링커리어 > 씽굿 순으로 확장. 같은 출처의 공모전·대외활동 메뉴 간 중복도 묶이는지 테스트
- 배치: `backend/batch.py` `run_external`과 `scripts/run_batch.ps1`의 `$externalSources`에 추가. 출처 하나가 실패·멈춰도 나머지는 계속(지금 동작 유지)
- 앱: 출처 이름 표시가 `source_id`→이름 대응표를 쓰면 새 출처 추가. 다른 화면 변경 없음
- 문서: SPEC.md(§2 범위, 출처 목록, 버전), `docs/decisions.md` 새 결정(번호는 파일의 가장 큰 번호 다음. #171·카톡 전달 작업과 겹치면 다음 번호), 약관·처리방침의 출처 서술(`docs/legal/`)

## 5. 건드리지 않을 것

- 규칙 분석기 `rules.py`·LLM 분석 (#170·#171 작업 중). 분석 오류는 보고만
- 위비티·콘테스트코리아 공모전 동작
- 인턴·채용 메뉴, 주최 측 따라가기, 캠퍼스픽·요즘것들·대티즌(D-038 제외)
- 헤드리스 브라우저·새 라이브러리 추가
- `Gwittim-batch` 폴더 갱신, Firestore 반영 (병합 뒤 팀장 지시로)
