## 2. 정보 세 층

### 2.1 기본 (이미 프로필에 있음, 매 요청 전송)

학교, 학과, 학년, 재학 상태, 관심사, 직무 (D-039 지킬 선 그대로)

### 2.2 요청 때만 (새로 추가, 모두 선택)

| 질문 | 칩 (여러 개 선택) | 왜 묻는지 (화면 한 줄) |
|---|---|---|
| 해 본 것 | 파이썬, 자바, 웹 화면, 앱 개발, 데이터 분석, 디자인 도구, 영상 편집, 팀 프로젝트, 공모전 참가, 대외활동, 현장실습·인턴, 아직 없음 | 해 본 것이 있으면 '맞는 점'에 반영합니다. |
| 가능한 시기 | 학기 중, 방학, 상관없음 (하나) | 활동 기간이 맞는지 비교합니다. |
| 갈 수 있는 지역 | 서울, 경기·인천, 온라인만, 상관없음 (여러 개) | 활동 장소가 맞는지 비교합니다. |

- 칩 목록은 제안이다. 공통 사전에 넣으려면 AGENTS.md §3 절차(계약 변경 PR)를 밟는다.
- 서버는 사전에 없는 값을 받으면 버린다(오류가 아니라 무시). 상세 분석에는 자유 글을 받는 경로 자체를 두지 않는다.
- 서버에 저장하지 않는다. 사용자가 "다음에도 이대로"를 켜면 **기기에만** 둔다('졸업생 진로 추천' 답과 같은 방식).

### 2.3 외부 공고 찾기 입력 (2026-11-21 결정)

- 기본은 버튼: 공고 분류(공통 사전), 관심 분야(프로필 사전), 가능한 시기·갈 수 있는 지역(§2.2 칩과 같은 목록)
- 선택으로 한 줄 직접 적기: 최대 50자. 칸 바로 아래 안내 "적은 문장은 AI(DeepSeek)에 보내집니다. 이름·연락처 같은 개인정보는 적지 마십시오."
- 직접 적은 문장은 검색에만 쓰고 저장하지 않는다. 요청이 끝나면 버리고, 로그·사용 내역·저장본 키에도 남기지 않는다
- 50자를 넘으면 서버가 거절한다(자르지 않음). 빈 문장은 적지 않은 것으로 본다

### 2.4 받지 않음

이름, 이메일, Firebase UID, 학번, 성적, 연락처, 자유 입력 글(자기소개·포트폴리오 등). 예외는 §2.3의 외부 공고 찾기 한 줄(선택, 저장 안 함)

## 3. LLM 제공자 나누기

`backend/agent/llm.py`에 제공자 한 겹을 둔다. 환경변수 `GWITTIM_LLM_PROVIDER`로 고른다.

| 값 | 동작 | 쓰는 곳 |
|---|---|---|
| `fake` (기본) | 고정 JSON 리포트를 돌려준다 | 테스트, 밤 작업 |
| `cli` | 로컬 `claude -p --model haiku`를 하위 프로세스로 부른다 | 팀장 PC에서 팀장 본인 개발·시연만 |
| `api` | Anthropic Messages API, 모델 Haiku 5.5, 키는 `ANTHROPIC_API_KEY` | 되돌릴 때를 위해 남겨 둠 |
| `deepseek` | DeepSeek Platform Chat Completions, 모델 `deepseek-flash`(V4.1 Flash), `reasoning_effort: none`(생각 끔), `json_object` 모드, 키는 `DEEPSEEK_API_KEY` | 결제 후 Cloud Run (D-044) |

- `cli`는 Cloud Run에서 켜지면 시작을 거부한다(`K_SERVICE` 환경변수가 있으면 예외). 구독 계정을 다른 사용자 요청 처리에 쓰지 않기 위함이다.
- `api`·`deepseek` 키가 없으면 상세 분석 경로는 "준비 중" 응답을 낸다.
- `deepseek`는 JSON 스키마 강제가 없다. 4칸은 서버가 검사하고, 빠지면 실패·환불로 처리한다. 상세 분석에는 웹 검색 도구를 붙이지 않는다(외부 공고 찾기에서만 검토).
- 시연 영상은 `cli`로 찍는다. 영상·소개 문서에는 "시연은 개발용 연결, 서비스 때는 API"라고 적지 않아도 되지만, 비용 수치는 D-039의 API 가격 기준으로 말한다.
- API로 바꿀 때 코드 수정 없이 `GWITTIM_LLM_PROVIDER=deepseek`와 키만 바꾼다. 같은 프롬프트·같은 JSON 칸을 쓰므로 제공자끼리 결과 형식이 같아야 한다(P2 테스트).
- 새 라이브러리 없음. `api`·`deepseek`는 표준 라이브러리 `urllib`로 부른다(SDK 추가는 별도 승인).
- 프롬프트 원문·응답 원문을 로그에 남기지 않는다. 남기는 것: 요청 시각, 공고 id, 토큰 수, 비용, 성공 여부.

## 4. 보관과 삭제

| 대상 | 기간 | 지우는 곳 |
|---|---|---|
| 요청 때 칩 값 | 요청이 끝나면 버림 | 서버 메모리만 |
| 외부 공고 찾기 직접 입력 (§2.3) | 요청이 끝나면 버림. 로그·내역에도 남기지 않음 | 서버 메모리만 |
| 리포트 저장본 | 공고 마감일 + 30일(마감 시각이 없으면 그 날 0시 KST 기준). 마감일이 `null`이면 생성 후 60일 | 하루 배치에서 `expires_at` 지난 것 삭제 |
| 리포트 저장본 | 탈퇴 즉시 | 기존 탈퇴 삭제에 추가 |
| 동의 기록 (버전, 시각) | 탈퇴 때까지 | 프로필과 함께 |
| 크레딧 내역 (§10) | 최근 90일, 탈퇴 즉시 | 하루 배치, 기존 탈퇴 삭제 |
| DeepSeek 쪽 입력·출력 | 정해진 기간 없음("목적 달성 시 파기"). 모델 학습에 쓰일 수 있음. 학습 거부 설정은 있으나 API 요청에 적용되는지 밝히지 않음 (DeepSeek 개인정보처리방침 2026-05-06판, 2026-11-22 확인) | DeepSeek |

- 같은 공고·같은 입력이면 저장본을 준다(D-039). 저장본 키는 `공고 id + 보낸 값 전체 + 지침 버전(backend/agent/harness/VERSION)의 SHA-256`. 지침을 고쳐 버전을 올리면 같은 입력도 새로 만든다(2026-11-23). 프로필이나 칩이 바뀌면 키가 달라져 새로 만든다.
- 마감일 `null`을 임의로 확정하지 않는다(AGENTS.md §1). 그래서 생성일 기준 60일을 따로 둔다.

## 7. 하지 않는 것

- Cloud Run·Firestore 쓰기, 배포, 보안 규칙 변경
- 구독 CLI를 서버 배포본이나 다른 사람 요청에 연결
- 새 라이브러리(Anthropic SDK 포함) 추가
- SPEC·`contracts/`·공통 사전 수정 (P6에서만)
- 프롬프트·응답 원문을 파일이나 로그로 남기기
- 실제 사용자 프로필로 시험 (합성 프로필만)

## 8. 검토 때 볼 것

- **새는 곳**: 보낼 값에 이름·이메일·UID가 들어갈 경로가 하나라도 있는가. 로그·예외 메시지에 프로필 값이 찍히는가
- **구독 우회**: `cli`가 서버에서 켜질 수 있는 경로가 있는가
- **기간**: 마감일 `null`을 어떤 날짜로 채우지 않았는가
- **문구**: 처리방침·동의 화면에 적은 것이 실제 동작과 같은가

## 9. 열린 사항

- DeepSeek 처리방침의 학습 이용·보관 조항은 2026-11-22 확인. 이용약관(Open Platform)은 자동 조회가 막혀 사람이 읽고 확인 필요(P8)
- 국외 이전 고지 범위의 법적 판단은 확인 전(P8)
- 칩 목록이 학과별로 충분한지 사용자 테스트(4주차)에서 확인
- **TBD: 4주차 사용자 테스트 5명 때 상세 분석을 어떻게 돌릴지.** 구독 CLI로 다른 사람 요청을 처리하지 않는다. 후보: 그 전 API 결제 / 에이전트 부분만 팀장이 조작
- 서버 전체 하루 상한(약 300건)은 `deepseek` 연결 때 정한다

## 10. 크레딧 (2026-11-19 결정: 따로 페이지)

규칙은 D-039 그대로: 가입 5, 매일 1 충전, 최대 5, 상세 분석 1, 외부 공고 찾기 2, 받은 리포트 다시 보기 무료.

### 10.1 들어가는 곳

- 내 정보 화면에 "크레딧" 줄(남은 개수 표시) → 크레딧 페이지
- 상세 분석 버튼의 "남은 n개"를 눌러도 같은 페이지

### 10.2 크레딧 페이지

- 맨 위: 보유 `3 / 5`, "다음 충전: 내일 0시 (+1)". 5개일 때는 "최대 보유. 사용하면 다음 날부터 다시 충전됩니다."
- 규칙 안내 한 칸: 매일 1개, 최대 5개, 상세 분석 1개, 외부 공고 찾기 2개, 다시 보기 무료
- 사용 내역 (최근 90일, 최신순)
  - `+5 가입 선물`, `+1 매일 충전`, `−1 상세 분석 · 공고 제목`, `−2 외부 공고 찾기 · 고른 버튼`(직접 적었으면 끝에 `· 직접 입력` 표시만. 적은 문장은 보이지 않음)
  - 차감 줄을 누르면 그 리포트(저장본)로 간다. 저장본이 만료됐으면 "보관 기간이 지나 삭제된 분석입니다."
  - 실패해서 차감하지 않은 요청은 내역에 넣지 않는다
- 광고 충전·유료 충전 버튼은 두지 않는다(D-039)

### 10.3 계산 규칙 (서버가 기준)

- 잔액은 서버만 쓴다. 앱은 읽기만(보안 규칙으로 클라이언트 쓰기 막음)
- 매일 충전은 크론 없이 **읽거나 쓸 때 계산**: 마지막 충전 날짜(KST)부터 오늘까지 지난 날 수만큼 +1, 5에서 멈춤. 채운 날마다 내역 한 줄
- 차감은 두 단계다. AI를 부르기 **전에** 크레딧을 잡아 두고(잔액 부족·이미 처리한 요청·진행 중인 요청이면 AI를 부르지 않음), 분석이 성공하면 확정한다. 실패·시간 초과는 잡아 둔 크레딧을 돌려준다. 10분 안에 확정되지 않은 잡아 두기는 자동으로 돌려준다
- 같은 요청 id로 두 번 차감하지 않는다(재시도 안전)
- 동시 요청(연타)은 저장소 트랜잭션 안에서 잔액 읽기부터 잡아 두기까지 한 번에 처리해 막는다
- 저장본이 있는 같은 공고·같은 입력은 D-039대로 차감하되 LLM을 부르지 않는다
