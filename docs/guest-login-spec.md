- 팀장 결정(2026-11-25): Firebase 익명 로그인으로 구현, 게스트 크레딧 3개(처음 2개에서 같은 날 변경: 상세 분석 1 + 외부 공고 찾기 2를 한 번씩), 게스트 정보 보관 30일

## 1. 지금 구조 (2026-11-25 main 기준)

- 앱: `lib/main.dart`가 서버 주소가 있으면 `AuthGate`(`lib/auth/auth_gate.dart`)를 띄움. 로그인 수단은 `FirebaseAuthService.signInWithGoogle()` 하나(`lib/auth/auth_service.dart`)
- 서버: `backend/api/app.py`의 `current_uid`가 `deps.verifier.verify(token)`으로 uid만 받음. `FirebaseTokenVerifier`(`backend/firebase_store.py`)는 `verify_id_token(...)["uid"]`만 돌려줌 → 익명 토큰도 지금 그대로 통과하지만 게스트인지 서버가 모름
- 크레딧: `backend/agent/credits.py` `SIGNUP_GIFT = 5`, `DAILY_CHARGE = 1`, `MAX_CREDITS = 5`. 첫 사용 때 `signup(now)`(호출: `agent/service.py`, `agent/external.py`)
- 탈퇴: 앱 `deleteAccount`는 Google 재확인 → `DELETE /v1/profile`(저장·리포트·크레딧·프로필 삭제) → Firebase 계정 삭제 (D-024)

## 2. 동작 정의

| 항목 | 게스트 | Google 로그인(변경 없음) |
|---|---|---|
| 들어가기 | 로그인 화면의 '로그인 없이 둘러보기' | Google 버튼 |
| 계정 | Firebase 익명 계정(uid 있음) | Google 계정 |
| 공고·추천·저장·프로필 | 같음(서버에 uid로 저장) | 같음 |
| 크레딧 | 처음 3개, 매일 충전 없음 | 처음 5개, 매일 1개, 최대 5개 |
| 상세 분석·외부 공고 찾기 | 같음(동의 화면 포함) | 같음 |
| 나가기 | '게스트 끝내기': 서버 정보와 계정을 지움 | 로그아웃 / 탈퇴 |
| 보관 | 만든 날부터 30일 뒤 삭제 | 탈퇴 전까지 |

- 게스트를 Google 계정으로 이어 쓰기(계정 연결)는 **이번에 만들지 않음**
- 게스트에게 프로필 값을 미리 채우지 않음(사용자 정보를 추정하지 않음). 첫 로그인 프로필 3단계는 지금과 같게 뜸

## 3. 서버

### 3.1 게스트 판별

- Firebase ID 토큰의 `firebase.sign_in_provider == "anonymous"`이면 게스트
- `TokenVerifier`가 uid와 게스트 여부를 함께 돌려주게 바꿈(작은 값 객체 또는 두 번째 메서드, 구현자가 고름). `current_uid`를 쓰는 기존 경로는 그대로 동작해야 함
- `FakeTokenVerifier`(`backend/api/deps.py`)와 로컬 서버(`backend.api.local`)에서도 게스트 토큰을 만들 수 있게 함(시험용)
- 게스트 여부는 요청마다 토큰에서 읽음. 프로필·크레딧 문서에 게스트 표시를 저장하지 않음(계약 `user_profile` 변경 없음)

### 3.2 크레딧

- `GUEST_SIGNUP_GIFT = 3`. `signup(now, guest=True)`면 3개로 시작
- 게스트는 매일 충전을 받지 않음: `current_state` 등 충전이 일어나는 곳에 게스트 여부를 넘겨 건너뜀. `next_refill_at`은 게스트에게 늘 `null`
- 잡아 두기·확정·환불(두 단계 차감), 월 비용 상한(`GWITTIM_LLM_MONTHLY_CAP_KRW`)은 그대로 적용
- 시연용 채우기(`POST /v1/credits/demo-refill`, 서버 설정으로 켰을 때만)는 게스트에게도 그대로 동작(5까지)
- 계약 `contracts/credits.schema.json`: 구조는 안 바꿈. 설명 문구만 고침(`signup` 금액 "+5, 게스트 +3", `next_refill_at` "게스트는 null"). `fixtures/`에 게스트 응답 샘플 1개 추가

### 3.3 그 밖

- `DELETE /v1/profile`은 게스트도 그대로 씀(변경 없음)
- `firestore.rules`는 바꾸지 않음. `signedIn()`에 익명도 포함되어 게시된 공고 읽기가 허용되지만 공개 공고뿐이고 앱은 서버 API만 씀. PR에 한 줄로 적어 둠
- 로그에 게스트 여부를 남길 때 uid·토큰은 지금 규칙대로(비밀값·개인정보 출력 금지)

## 4. 앱

화면·문구는 `docs/ui-style.md`를 따름(해요체 금지, 버튼은 명사형).

### 4.1 로그인 화면

- Google 버튼 아래에 글자 버튼 **'로그인 없이 둘러보기'**. 약관 줄은 지금처럼 맨 아래(게스트에게도 같은 동의 문구가 적용됨)
- 버튼 아래 작은 안내 한 줄: `게스트 정보는 30일 뒤 삭제됩니다.`
- 누르면 `AuthService.signInAsGuest()`(새 메서드, `FirebaseAuth.signInAnonymously()`). 실패하면 기존 로그인 실패와 같은 방식의 안내(상세 오류·스택 노출 금지)
- 화면 크기 맞춤 유지: 작은 화면·글자 1.3배에서 버튼 두 개와 약관 줄이 아래에 고정되고 넘치지 않을 것

### 4.2 내 정보

- `AuthService`에 게스트 여부를 알 수 있는 값 추가(`isGuest`)
- 계정 칸: 게스트면 '게스트로 이용 중' 한 줄과 **'게스트 끝내기'** 버튼만. 로그아웃·탈퇴하기는 숨김(게스트가 로그아웃하면 계정을 되찾을 길이 없음)
- '게스트 끝내기': 확인 창(지금 탈퇴 확인 창과 같은 모양, 문구 "저장한 공고와 내 정보가 삭제됩니다.") → `DELETE /v1/profile` → Firebase 익명 계정 삭제 → 로그인 화면. Google 재확인 단계 없음
- 기기에만 있는 기록(지원 건 상태, 학과 통계 추천 답, 브리핑 본 날 등)도 탈퇴 때와 같은 범위로 지움
- 끝낸 뒤 로그인 화면의 '탈퇴 완료' 팝업은 띄우지 않음

### 4.3 크레딧 화면

- 게스트면 다음 충전 시각 대신 `게스트는 매일 충전이 없습니다. Google 계정으로 시작하면 매일 1개가 충전됩니다.` 한 줄
- 잔액 0에서 상세 분석을 누르면 기존 크레딧 부족 안내가 그대로 나오는지 확인

### 4.4 건드리지 않는 것

- 샘플 모드(서버 주소 없는 빌드), 로컬 서버 모드, 시연용 빌드 플래그(`GWITTIM_DEMO`)
- 첫 로그인 프로필 3단계, 상세 분석 동의 화면의 내용
