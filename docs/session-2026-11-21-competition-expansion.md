# 세션 정리: 경쟁팀 비교와 확장 방향 (2026-11-21)

## 1. 경쟁팀 비교 — 페이체크 (내돈내놔 팀)

- 사이트: paycheck-pi.vercel.app / 저장소: github.com/yemurf/paycheck (공개)
- 무엇: 알바 근로계약서 사진 → AI가 시급·근무시간·기간 읽기 → 사람이 확인 → 규칙 코드가 판정 → 법 조문 근거 + 사장님께 보낼 문장
- 직접 체험(샘플 '약국 알바'): 실제 계약서 사진 읽음, 원문 인용 표시, 흐린 항목은 노란 카드로 확인 요청, 분석 약 15초
- 구성: Next.js + Claude API 사진 읽기 + 규칙 6종·테스트. 기여자 1명, 커밋 34개, 공개 저장소 마지막 푸시 11/6
- 강점
  - 문제 선명("사인 전 30초"), 설치·로그인 없이 샘플 체험
  - "AI는 읽고 설명만, 판정은 코드" 신뢰 설계. 판정에 없는 숫자가 나오면 설명 버림
  - 정보 → 행동(보낼 문장) 연결, 사회적 가치(노동권)
- 약점
  - 자체 데이터·모델 없음 ("LLM API + 규칙" 공격 가능)
  - 추출 정확도 수치 비공개, 일회성 사용, 조항 범위 좁음
- 2단계 40팀 포함 여부: 미확인

## 2. 대회 최종 심사 기준으로 채점 (aion2026.vercel.app)

- 일정: 최종보고서 12/11(금) 23:59 → 서면 사전평가 12/14~16 → 본선 시연·시상 12/18(금)
- 40팀 모두 시상(대상 1, 금 4, 은 8, 동 12, 장려 15). 실제 승부는 대상·금상

| 항목 | 배점 | 페이체크 | 귀띔 |
|---|---|---|---|
| 문제 해결 완성도·실용성 | 20 | 16 | 15 |
| AI 활용 고도화·창의성 | 20 | 13 | **18** |
| 결과 구현 완성도 | 25 | 21 | 20 |
| 협업·멘토링 반영도 | 10 | 6 | **9** |
| 확장 가능성·사회적 파급력 | 10 | **9** | 6 |
| 발표·시연 | 15 | **13** | 10 |
| 합계 | 100 | 78 | 77 |

- 주관적 추정. 서면(85점)은 귀띔 근소 우세 가능, 시연(15점)이 최대 위험
- 처음 일반 기준으로는 페이체크 우세로 봤으나, 실제 기준표의 "고도화" 항목 때문에 거의 동점으로 수정

## 3. 결정

- 시연 준비는 기능 확장(웹 에이전트 등) 뒤로 미룸 → [final-prep-todo.md](final-prep-todo.md)에 보류 목록
- **D-043** 확장 방향 뒤집기 ([decisions.md](decisions.md))
  - 전: 명지전문대 공고 기반 + 외부 공고 덧붙임
  - 후: 교외 공고 자동 수집(D-038)·맞춤 에이전트(D-039)를 어느 학교 학생이든 쓰는 기본층으로, 학교 공지는 "학교 팩"으로 얹음
  - 학교 팩 = 게시판 수집 설정 + 학과 사전·키워드 규칙 + 학과 통계 (+ 선택: 알림톡 수집기 폰)

## 4. 다른 학교 게시판 조사 → [school-expansion-review.md](school-expansion-review.md)

- 배화여대·숭의여대 모두 공지 게시판 로그인 없이 열림, robots가 게시판 경로 막지 않음, 이용약관 페이지 없음(이용 허락 미확인)
- 세 학교 게시판 시스템 모두 다름 → 학교당 파서 필요, 공통 파이프라인은 재사용
- 숭의: 서버 HTML 표, 본문 텍스트 → 붙이기 쉬움. 같은 CMS가 다른 대학에도 있을 가능성
- 배화: 목록은 JSON(POST), 본 1건은 내용이 PDF·HWP 첨부에만 → 첨부 처리가 관건. 목록 JSON에 게시자 IP 필드 있음(버릴 것)
- 숭의 robots가 특정 봇 11개 차단(AI 봇 + 일반 크롤러 섞임), 본문 이미지 경로(`/_attach`)도 차단 → 포스터에만 있는 내용은 못 읽음. 이용 허락 요청 때 LLM 분석 밝히기
- 첨부 파일은 두 학교 모두 robots가 허용하는 경로로 받음(11/21 다시 확인)
